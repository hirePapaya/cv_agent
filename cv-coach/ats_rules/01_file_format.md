# File Format

## Rules
- Submit as `.docx` unless the job posting explicitly requests `.pdf`. Older ATS parsers handle `.docx` more reliably.
- If `.pdf` is required or preferred, export from a text-based source (Word, Google Docs, LaTeX) — never a scanned image or flattened design-tool export.
- Use a single-column, linear reading order. Multi-column layouts, tables, and text boxes are frequently parsed out of order or dropped entirely.
- Avoid placing critical content (name, contact info, section headings) in headers/footers — many parsers skip them.
- No embedded images, icons, charts, or graphics that carry information (e.g., skill-level bars).
- File name: `FirstName-LastName-Resume.pdf` (or `.docx`) — avoid spaces, special characters, and version tags like "final_v3".
- Keep to one or two pages: one page for under 10 years of experience, two pages max otherwise.

## Why It Matters
ATS software extracts raw text before a recruiter ever sees the document. Anything that can't be cleanly extracted — graphics, columns, headers — becomes invisible or garbled text, which can silently remove a candidate from consideration.

## How to Apply
When reviewing a resume, flag: non-standard file types, multi-column layouts, embedded text in images, and content placed in headers/footers.
